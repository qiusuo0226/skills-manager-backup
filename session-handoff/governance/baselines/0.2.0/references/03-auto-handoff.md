# 自动交接

命中「开启自动交接 / 关闭自动交接」时加载本文件；首次整份交接后用户同意开启时也加载。

技能不能自己醒来，没有后台定时。这里的「自动」是被动触发：开启后，助手在对话走到检查点时顺手更新同一份记忆文件。

## 1. 三层

| 层 | 做法 | 是否必需 |
|---|---|---|
| (a) 会话级开关 | 第 2～5 节 | 是 |
| (b) 常驻规则片段 | 第 6 节；片段模板 `assets/templates/auto-handoff-rule.md` | 否（兜底） |
| (c) 平台 hook | 第 7 节 | 否 |

## 2. 开启

- 口令「开启自动交接」；或首次整份交接落盘后问一次「要开启自动交接吗？」，用户同意才开，拒绝则本会话不再问。
- 路径：已有记忆文件 → 沿用；没有 → 按 `01-write-memory.md` 第 2 节问一次路径并给建议。之后不再问（硬闸 3）。
- 记忆文件还不存在 → 先按 `01-write-memory.md` 整份交接写一份。
- 头注「自动交接」改为「开启（YYYY-MM-DD）」。
- 可提一次常驻规则片段（第 6 节），先问再写。

## 3. 检查点

出现下列任一情况就更新一次：

1. 拍板一项决定
2. 切换话题
3. 完成一步
4. 约每 10 轮（上限提示，不硬计数；模型数不准轮次）

闲聊、没有新事实的轮次不更新。

## 4. 怎么更新（增量）

1. 写前先读当前文件（硬闸 4），保留用户在两次更新之间的手改。
2. 只改受影响的话题节（多话题时第 10 节对应的 `T{n}`；单话题时对应的第 1～9、11 节）和第 0 节索引 / 当前焦点；不全文重写。
3. 过 `01-write-memory.md` 第 7 节自检；硬闸 1～7 全部照旧：无来源不写、秘密不写、待确认不进已拍板。
4. 只维护同一份文件：不生成快照、不另存时间戳副本、不要 `_v2`（硬闸 5）。
5. 写后只回一行，例如：`（已更新交接：T2 当前状态）`。不复述全文。

## 5. 关闭

- 口令「关闭自动交接」→ 之后检查点不再写盘。
- 头注「自动交接」改为「关闭」（关闭时最后一次写）。
- 若写过常驻规则片段，问一次是否删除；同意则按 BEGIN～END 标记整段删。

未开启时照常对话，不自动写盘。

## 6. 常驻规则片段（兜底，可选）

会话级开关只在本会话有效；对话很长或上下文被压缩后容易被忘。可在项目常驻加载的规则文件里放一段提醒：`AGENTS.md`、`CLAUDE.md`、Cursor 规则（`.cursor/rules/*.mdc`，需 `alwaysApply: true`）。

- 片段模板：`assets/templates/auto-handoff-rule.md`。只替换 `{记忆文件路径}`、`{开启日期}`；`{改了什么}` 运行时填写。
- **写入前先问用户**，说明写到哪个文件；未同意不写。拒绝后自动交接仍按会话级工作。
- 目标文件已有 `session-handoff:auto-handoff BEGIN` 标记 → 只更新占位，不重复追加。
- 关闭自动交接时问是否删除片段。

## 7. 平台 hook（可选）

部分平台可在回合结束或压缩上下文前触发钩子（例如 Claude Code 的 `Stop`、`PreCompact`），可自行挂上「按 session-handoff 更新记忆文件」的提醒。钩子名称与配置以各平台文档为准。技能不依赖 hook，也不替用户安装或配置。
