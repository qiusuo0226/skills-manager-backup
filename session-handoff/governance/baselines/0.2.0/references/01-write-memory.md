# 写记忆 markdown

加载本文件后再落盘。模板只读 `assets/templates/session-memory.md`，不要拿历史记忆当范本。

## 1. 模式

| 开口 | 模式 |
|---|---|
| 帮我记录一下上下文 / 会话交接 / 生成记忆 md | **整份交接**：按模板写齐各节 |
| 帮我记住下面的话 | **追加原话**：把用户指定的句子原样记下；若尚无记忆文件，用模板建一份，并补上能从本轮对话核实的最少上下文 |

两种模式都走下面的路径、合并、脱敏规则。

## 2. 保存路径

已有明确路径（含「写到当前目录」「覆盖这份」）→ 用它，不再问。

否则先问，并给出建议（建议可多给，让用户选或改）：

1. **当前工作目录**：`{工作区}/{目录名}会话交接.md`
2. **本机 Downloads**：`{用户主目录}/Downloads/{目录名}会话交接.md`

识别系统后再填建议：Windows / macOS / Linux 都先看 `{home}/Downloads` 是否存在；没有则退回 `{home}`。工作区若就是 Downloads、桌面或用户主目录，第 1 条改用对话主题做文件名，不要用 `Downloads会话交接.md` 这种空名。

用户回序号、回完整路径、或回文件名均可。未答之前不要写盘。

## 3. 收集什么

只写能核对的内容，每条标来源：

- 任务目标、角色、交付物路径
- 用户反复强调的约束（必须遵守）
- 依据材料（路径 + 在本任务里怎么用）
- 当前进度与当前工作稿（以用户指定的那份为准）
- 已拍板的事实
- 待确认 / 未完成（谁提供、对应哪一章或哪一步；不要写进「已拍板」）
- 下一场会话建议怎么开口、先读什么
- 禁止事项（从用户约束归纳，不发明新禁令）
- 决策与弯路：选了什么 + 为什么；否决了什么 + 为什么；试过什么失败了（第 11 节，或话题内「讨论要点」）

对话涉及多个话题时，先按第 8 节拆话题，再分别收集。

**篇幅分层**：第 0 节概览 ≤6 行，只说在做什么、当前焦点、下一步、最大阻塞，单独读也能看懂；不得出现下方各节没有的事实。细节全部写在下方各节。

**来源怎么标**：

- 行内写 `（来源：对话）` 或 `（来源：{相对或绝对路径}）`；表格用「来源」列。
- 一段内同源可在段尾统一标一次，减少噪音。
- 给不出来源的事实不写（硬闸 1）。

**决策与弯路**：表格 `决定 | 选定方案 | 理由 | 否决方案 | 否决理由 | 来源`；失败尝试单列一行「试过 X，因 Y 失败」。

「帮我记住下面的话」：把用户标出的句子放进第 9 节，逐条加日期；不要改写原话。多话题时可在日期后加 `〔T{n}〕` 标签，原话仍留在第 9 节。

## 4. 合并已有文件

目标路径已存在：

1. 先读全文
2. 用新事实更新对应节；被取代的旧结论删掉或改写成现行口径，不要两套并存
3. 话题按 T 编号对齐：新话题追加新编号；已解决话题压成 1～2 行（结论 + 来源）；进行中话题按新事实更新
4. 用户手写、且本轮未否定的内容保留
5. 第 9 节只追加，不删旧原话，除非用户明确说忘掉某条
6. 旧格式文件（没有第 0、10、11 节）：原内容不丢，补齐第 0、10、11 节

## 5. 禁止写入

- 编造的编号、人员、结论、路径
- 给不出来源（对话或已读文件）的事实
- 资源清单或对话里出现的口令、密钥、云方人员手机
- 「待某某确认」「请向谁回填」这类过程叮嘱——待办放第 6 节，写成谁提供什么
- 第二份过程稿、版本号后缀（不要 `会话交接_v2.md`）

## 6. 落盘后

用一句话说清：路径、本轮记了什么、是否合并了旧文件。提醒：下一场会话先读这份。

首次整份交接完成、且本会话未开启自动交接：告知后问一次「要开启自动交接吗？」。同意按 `03-auto-handoff.md` 开启；拒绝则本会话不再问。

## 7. 落盘前自检

整份交接、追加原话、自动更新（`03-auto-handoff.md`）都要过。自检不输出清单给用户，只在不过时按右列修正后再写；落盘告知一句不变。

| # | 检查 | 不过怎么办 |
|---|---|---|
| 1 | 每条事实能在对话或已读文件里找到 | 删掉 |
| 2 | 无口令/密钥/人员手机（「记住下面的话」原文除外） | 删值，只留约束 |
| 3 | 待确认事项不在「已拍板」第 5 节 | 移到第 6 节或话题「待办」 |
| 4 | 事实都有来源 | 补来源或删 |
| 5 | 仍是同一份文件，无 `_v2` 另存 | 改回原路径 |
| 6 | 多话题时索引表、当前焦点与第 10 节一致 | 修正 |

## 8. 话题拆分

| 规则 | 口径 |
|---|---|
| 聚类依据 | 按问题/话题，不按时间顺序 |
| 断点重连 | 话题 A 被 B 打断后又回到 A → 并入同一 T 编号 |
| 不拆 | 全程只有 1 个话题 → 不出第 10 节拆分（写「单话题，未拆分」），保持原九节结构（第 0 节仍写，索引只 1 行） |
| 不成话题 | 闲聊、已纠正的口误 |
| 过细合并 | 同一问题的子步骤不单列；拿不准就合并 |
| 公共部分 | 全局约束（第 2 节）、禁止事项（第 8 节）、原话（第 9 节）留在公共节；第 9 节原话可加 `〔T2〕` 标签，不搬家 |
| 依赖 | 话题间依赖写在索引表「依赖」列（如 T3 依赖 T1 结论） |
| 编号稳定 | T 编号一旦分配不重用、不重排 |
| 合并旧文件 | 按 T 编号对齐：新话题追加新编号；已解决话题压成 1～2 行（结论 + 来源）；进行中话题按新事实更新 |

第 10 节每个 `### T{n} {标题}` 固定六项：问题是什么、背景、讨论要点（试过什么 / 否决了什么及原因）、当前状态（已解决 / 进行中 / 搁置）、待办、相关文件。第 0 节「当前焦点」写最后在讨论的话题。
