# 交付物模板结构

> 本文件是章节与表头的唯一字段源。`assets/templates/` 是空骨架，`scripts/validate_deliverables.py` 顶部常量必须与本文件逐字相同。公司数量与岗位方向可变，章节与表头固定，Agent 只填数据。

---

## 一、公司深度介绍 Word 文档

**文件名格式：** `{公司名}_深度介绍_{YYYYMMDD}.docx`

**骨架：** `assets/templates/company-profile.docx`

Word 内可对薪资/风险做短摘要，数字必须与两个 xlsx 同口径，不替代 Excel。

### 封面/标题区

- 标题：`{公司名} 求职深度调研报告`
- 副标题：面向 `{用户岗位方向}` 岗位 / `{目标城市}`
- 报告日期、数据采集时间范围
- 免责声明：本报告基于公开信息整理，仅供求职参考，不构成入职建议；信息可能存在滞后，请以官方最新信息为准。

### 1. 报告摘要与核心结论

结论表行：公司定性、岗位定性（无 JD 则写「未提供具体 JD」）、薪资水平、财务健康、扩张/收缩、匹配度、总体建议。文末一句证据分级 A/B/C/D。

### 2. 岗位 JD 解读

小节标题必现：岗位基本信息、岗位职责与要求解读、异常点提示。无 JD 时本章保留，写「未提供具体 JD，据公开招聘信息整理」或「待补充」，禁止删章。

岗位基本信息表可含：岗位名称、招聘方、薪资范围、地点、学历、经验、标签、信息获取时间。

### 3. 公司基本信息

| 项目 | 内容 | 来源 |
|------|------|------|
| 公司全称 | | 工商登记 |
| 成立时间 | | 工商登记 |
| 注册资本/实缴资本 | | 工商登记 |
| 法定代表人 | | 工商登记 |
| 公司类型 | 国企/民企/外企/上市公司 | 工商登记 |
| 员工规模（参保人数） | | 工商登记（注明年份） |
| 上市情况 | 如上市，注明板块/股票代码 | 交易所 |
| 总部/分支机构 | | 工商登记/官网 |
| 主营业务 | | 官网/财报 |

可在表内追加统一社会信用代码、资质荣誉等行。

### 4. 股权与关联方

控股/联营/员工持股/是否并表。无公开信息则「待补充」，不得省略标题。

### 5. 业务与行业地位

- 主营业务板块、产品与客户（ToG 重点列政府客户、中标项目）
- 行业地位：市场份额/排名/行业标签，必须注明来源
- 竞争对手
- 近期业务动态
- 有上市母公司或明显集团时写清协同，并写「不得把母公司经营直接等同本公司」

### 6. 扩张与收缩信号

- **扩张信号：** 融资、招聘规模、新城市/新业务、中标、分支机构新增
- **收缩信号：** 裁员、岗位冻结、业务线关停、场地缩减、高管变动、应收账款异常
- **综合判断：** 分业务线；每个信号带来源和证据等级

### 7. 财务健康度

营收/净利润趋势、应收账款、现金流、研发投入。无独立财报时允许用关联上市主体，必须标明口径不是本公司。

### 8. 组织与职级体系

组织架构、职级体系、晋升机制、培训与成长。未知则待补充，不得省略标题。

### 9. 个人匹配度分析与面试建议

小节标题必现：用户背景摘要、与岗位要求逐条对照、匹配点与差距点、投递与面试策略。无用户背景时写「用户背景未提供，以下仅客观分析公司与岗位」；逐条对照改为岗位常见要求；禁止删章、禁止编造用户经历。

### 10. 信息来源清单

名称、URL、访问时间。

### Sheet：风险提示清单

| 风险等级 | 风险类型 | 具体描述 | 证据来源 | 证据等级 | 对用户的影响 | 建议 |
|---------|---------|---------|---------|---------|-------------|------|
| 高/中/低/待核实 | 裁员/薪资拖欠/管理混乱/业务收缩/回款困难/加班严重/等 | | | A/B/C/D | | |

### Sheet：面试建议提问清单

| 关注方向 | 建议提问 | 目的 |
|---------|---------|------|
| 岗位定位 | "这个岗位是新设还是补缺？汇报对象和团队规模？" | 判断真实定位 |
| 学历门槛 | "JD 学历要求是硬性门槛还是发布误设？" | 核实硬门槛 |

| 公积金 | "公积金缴纳基数和比例是多少？是按实际工资还是固定基数？" | 核实隐性收入 |
| 加班 | "团队目前加班情况如何？有调休或加班费吗？" | 核实工作强度 |
| 团队稳定性 | "这个岗位是新增还是替补？团队近半年人员流动情况？" | 判断是否坑位 |
| 业务前景 | "这个业务线/项目的预算和人员规划是怎样的？" | 判断业务是否稳定 |
| 出差 | "岗位出差频率和补贴标准是怎样的？" | 核实出差情况 |
| 年终奖 | "年终奖通常是几个月？近三年实际发放情况？" | 核实年终是否靠谱 |

Agent 只改写成与本案相关，不得删表。

## 四、交付物生成注意事项

1. Word 使用 `python-docx` 或环境 Word 能力，中文字体宋体/微软雅黑。
2. Excel 使用 `openpyxl`，表头加粗，高风险标红。
3. 所有交付物须有信息来源清单（Word 专章；Excel 在各 Sheet 说明或另附来源列）。
4. 仅当用户在交付物声明之后明确只要其中若干份时，才可少交；未声明则三类全出。
5. 未上市公司且公开信息极少时，报告开头注明「该公司公开信息有限，部分内容基于有限样本，仅供参考」。
6. 不得出现无法溯源的数据，宁可留空标注「待补充」，也不编造。
7. 生成后必须通过 `scripts/validate_deliverables.py`，失败禁止交付。
